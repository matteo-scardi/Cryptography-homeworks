Overview: Private Key → Public Key Derivation

In Ethereum and elliptic-curve cryptography, a private key is simply a secretly chosen integer k. The corresponding public key is a point Q = k · G on the curve, computed by performing scalar multiplication: adding the standardized base point G to itself k times using the curve's chord-and-tangent group law.

This operation serves as an algebraic one-way function: computing Q = k · G in the forward direction is deterministic and fast (via Double-and-Add), but determining the secret scalar k from the known points Q and G is computationally infeasible. This mathematical hardness is the Elliptic Curve Discrete Logarithm Problem (ECDLP).

Cryptographic Analysis: OWF vs Hash Functions

Elliptic Curve Multiplication (k · G)

  • One-Way Function (OWF): Easy forward: O(log k) via Double-and-Add. Hard backwards: requires solving the ECDLP (O(√n) Pollard-rho).
  • Algebraic Homomorphism: Preserves group structure: (k₁ + k₂)G = k₁G + k₂G. Crucial for Schnorr signatures, ECDSA, and threshold cryptography.
  • Non-Uniformity: Outputs are strictly constrained to the curve's abelian group manifold; coordinates are not uniform integers.

Cryptographic Hash Functions (Keccak-256)

  • Destroys Homomorphism: Zero algebraic relations remain: H(x + y) ≠ H(x) + H(y).
  • Strict Avalanche Criterion (SAC): Flipping 1 input bit flips exactly ~50% of the output bits with zero correlation.
  • Uniform Random Oracle: Output distribution is indistinguishable from a true uniform random bit generator.
