Private Key → Public Key in Ethereum

Homework 1 – Elliptic-Curve Scalar Multiplication as a One-Way Function

📚 Project Description

Elliptic-curve scalar multiplication is easy in one direction and hard in the other: given a private key k and a base point G, the public key Q = kG is computed quickly, but recovering k from Q is the Elliptic Curve Discrete Logarithm Problem (ECDLP). Ethereum uses the curve secp256k1.

private key k → Q = k·G (public key) → Keccak-256(Q) → Ethereum address

This page uses the toy curve y² = x³ + 7 (mod 17) with G = (1, 5) and k = 6. It adds a slowed-down visualizer, a statistical exploration on larger toy curves, and a real secp256k1 / Ethereum-address demo. The goal is understanding, not a real cryptosystem.

Conclusion. Statistical tests can reveal weaknesses but cannot prove one-wayness: kG looks random yet is computed with a simple public formula. Its security comes from the hardness of ECDLP, not from statistical mixing. In Ethereum both worlds are chained: the ECC one-way map k → Q, then Keccak-256 to derive the address.
