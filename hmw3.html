ECC Toy Scheme, Caesar Cipher & Cryptanalysis

Encryption, Key Spaces, Statistical & Discrete-Log Attacks

📚 Project Description

This page implements and compares two very different ciphers on the same message: a toy ElGamal/ECIES-style scheme over the secp256k1 elliptic curve (private key restricted to 16 bits) and the classical Caesar cipher. It then breaks both: the Caesar cipher through chi-squared letter-frequency analysis, and the toy ECC scheme through a Baby-Step Giant-Step discrete-logarithm attack that exploits the small key space.

The results highlight how statistical leakage and key-space size, rather than the algebraic structure alone, determine the security of a scheme. Everything runs locally in your browser.

Encrypt & Decrypt (secp256k1)

Algorithm & Role of the Keys

Key generation

Private key d ∈ [1, 65535] (restricted). Public key Q = d·G.

Encryption

Random ephemeral k; C1 = k·G; shared secret S = k·Q; keystream SHA-256(S.x ‖ i); C2 = m ⊕ keystream.

Decryption

S = d·C1 = dk·G = k·Q. Same keystream, so m = C2 ⊕ keystream.

Roles: Q and C1 are public. Only d (or k) lets one rebuild S.

Caesar Cipher

Encryption: C = (P + k) mod 26   Decryption: P = (C − k) mod 26. Non-letters are left unchanged.

Similarities & Differences

AspectCaesarToy ECC scheme
TypeSymmetric, monoalphabetic substitutionAsymmetric (public/private key), hybrid with hash keystream
EncryptionShift each letter by kScalar multiplications + XOR with hashed shared secret
DecryptionShift back by kS = d·C1, regenerate keystream, XOR
Key space26 (≈ 24.7)216 in the toy; ≈ 2256 in real ECC
RandomnessDeterministic: same plaintext gives same ciphertextProbabilistic: fresh k gives a different ciphertext every time
StatisticsLetter frequencies preserved (only shifted)Output looks uniformly random; no plaintext statistics leak
Best attackFrequency analysis / exhaustive searchDiscrete-log solving (BSGS) thanks to tiny d

Common ground: both are deterministic once the secret is known, and both are only as strong as the secret's search space. Key difference: Caesar fails statistically, while the toy ECC fails only because of its restricted key range.

Chi-Squared Key Recovery

For each shift s we decrypt and compute χ² = Σ (Oi − Ei)² / Ei against English letter frequencies. The lowest χ² wins.

Effectiveness vs. Ciphertext Length

200 random trials per length, using random fragments of an English corpus and random keys.

Limitations: short texts give too few samples, so the distribution is noisy. Non-English or unusual text breaks the language model. Alternatives: exhaustive search needs human or dictionary checks. n-gram (bigram/quadgram) log-likelihood scoring is more robust on short texts.

Baby-Step Giant-Step on Q = d·G

Search space N = 216, m = 256. Store j·G for j < m (baby steps), then compute Q − i·(m·G) until it matches. Then d = i·m + j. Cost: about √N = 28 group operations.

Discussion

  • vs. Caesar attack: Caesar leaks plaintext statistics. The ECC output has no such bias, so we solve a discrete log instead.
  • Real ECC: with d ≈ 2256, the best generic attack (Pollard’s rho) costs ≈ 2128 operations, which is infeasible.
  • From the key space: brute force and BSGS.
  • From the design itself: no authentication (XOR is malleable), catastrophic k reuse (C2⊕C2' = m⊕m'), no padding (length leaks), and no validation that C1 lies on the curve.
